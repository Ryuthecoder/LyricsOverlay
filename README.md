# Project Brief

## Pivot in Milestone 2

## Problem
Problem: From relaxation to productivity tools, there are many tools that people may wish to have, but they simply do not exist because the demand for each one is too small to justify a whole app. For example, gamers enjoy listening to music, and some people prefer to sing along with the song; yet, they are not able to do so because there is no live-lyrics overlay because there is limited demand for a single purpose application like lyrics overlay, with a sole purpose of displaying live lyrics. Moreover, students at ASIJ may desire a visual calendar or timeline that allows them to look at the days leading up to assignment deadlines, solely focused on such due dates and not days or non-assignment events that may otherwise appear on a traditional calendar. Therefore, there are many both relaxation or gaming and productivity issues that people seek solutions. A widget system addresses these untapped needs: each widget serves one specific purpose that would otherwise never be built as a standalone app. 

## Criteria

### Software
- The widget system must have common aesthetics, including a simple and minimalistic design that blends seamlessly with the native macOS desktop.

**Live Lyrics Widget**
- The program must show lyrics that are synced with the Spotify player at a reliable (consistent connectivity) pace.
- The program must require little to minimal steps to set up the program.
  - It must be easy for users who do not have experience with programming to set up.
- It must not breach the TOS of Spotify.
- The program supports many lyrics from different types of music to match the diverse music taste of the gamers.

## Constraints

### Software
- The program load can be run on macOS smoothly, with no computational bottlenecks
- The program must rely on free APIs to ensure the longevity of the program.
  - Minimal funds are provided by the school.

## Areas of Learning

Specifically, the Qt framework has a specific concept of signals and slots, which is a feedback system that allows live interactions across classes or methods using ever-changing live data. Working and thinking of code projects as an active program, not traditional static programming, challenges me to consider this new live aspect in my project.
- **(New Language) Python:** While I have learned Java since last year, I have not touched Python before. Learning and working with different syntax and properties will force me to make connections between previously learned Java concepts and that of Python and, more challengingly, let go of habits or concepts from Java that would otherwise contradict those of Python.
- **(New APIs) Spotify and LRCLIB Web APIs:** HTTP request. While it has a universal interface, none of my past coding experiences have interacted with it, and application of HTTP request involves a deeper understanding of the backend of API and server responses. As many software projects, both at a personal level and potentially professional level, rely on API or server messagings, this challenging concept will not only challenge me but also prepare me to tackle future personal or professional projects.
